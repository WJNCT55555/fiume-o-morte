### 2.2 `ev_1922_10_roma` → `ev_marcia` 的时序矛盾（重要）

```js
// ev_marcia.ts 选项 a —— 既置 march_on_rome，又置 coup_done
effect: { flags: { march_on_rome: true, coup_done: true }, ... , forceEndingCheck: true }

// reducers.js checkEnd —— 已政变时立即硬结束
if (s.flags.coup_done && !s.flags.exile && !s.flags.stay && !s.flags.march_on_rome) hardEnd = true;
```

`ev_coup` 的触发条件是 `事态 ≥ 100 且 日期 ≥ 1922-03`，而 `ev_1922_10_roma` 排在 **1922-10**。
**正常情况下 1922-03 政变已经发生并结束对局**，玩家根本活不到 1922-10。
即使活到，`coup_done` 一旦为真就会在 `checkEnd` 里立刻 `hardEnd`。

**结论**：1922 版进军线是**时序上自相矛盾的死内容**，应在本次重构中剪除。

现状：`carta` 日志有 12 处平行入口，无阶段。**建议改为四阶段链**：

```
阶段 1 起草    ← ev_1920_01_deambris（德·安布里斯抵达，已实现，单选项）
                 产物：flags.charter_drafted
```

**每个阶段只保留一个入口**，删除 `ev_strike` / `ev_factory` / `gv_arengo` 里的平行

### 3.3 危机的分离（当前最大的机制缺陷）

**问题**：意大利武力收复与法西斯政变共用 `order.coup` 一个数值与一套里程碑，
玩家无法分辨「罗马要来打我了」还是「墨索里尼要来接管运动了」。

**建议**：拆成两条独立危机轴。

| 轴 | 字段 | 驱动 | 里程碑 | 终局 |
| --- | --- | --- | --- | --- |
| **外部：罗马的耐心** | 新 `order.siege`（或复用 `coup` 改名） | 意大利关系、封锁、国际承认、合法性 | 切断汇款 → 封锁收紧 → 卡维利亚最后通牒 → 皇家陆军进攻 | `ending_natale` / `ending_historical` |
| **内部：法西斯接管** | 新 `order.subversion` | 法西斯派影响力、`squadre`、暴力、全国法西斯进展 | 党部设立 → 街头枪击 → 君塔小队进城 → 进攻省督府 | `ending_fascio` / `ending_civil_strife` |

**关键**：两条轴**互相独立地累积**，且都能在同一局里同时逼近——这时玩家必须在
「对外妥协」与「对内镇压」之间取舍。这正是史实上邓南遮失败的真正结构。

**最小改动实现**：保留 `order.coup` 作为**外部轴**（改名 `siege`），新增 `order.subversion`
作为内部轴，`R.coupMilestones` 拆成两个函数，`ev_natale` 读 `siege`，`ev_coup` 读 `subversion`。

### 3.9 连带修掉的一个潜伏 bug：`carta` 的失败条件

```js
// 改前
fail: function (s) { return s.laws.statuto === 0 && s.monthIndex > 7; }
```

`monthIndex` 是**从 1919-09 起的半回合计数**，7 意味着「1920 年 2 月」。
而阶段 2 使日志固定在 **1920-09 前后开启（monthIndex ≈ 24）**——
**旧条件下日志一开启就会在下一次结算立刻判失败**，玩家根本来不及行动。
这个 bug 在改成四阶段链之前是隐性的（因为那时有 12 个入口，最早的在 1919-09 就会点亮）。

改为绝对日期：`s.date.y > 1921 || (s.date.y === 1921 && s.date.m > 8)` → **1921 年 8 月截止**，
给出「从宣读起一年」的实施窗口，与史实（1920-09 颁布、1920-12 摄政垮台）相称。
`goal.fail` 的文案同步改写。

**可达性实测**（`.analysis/check_carta_chain.js`，30+ 项断言全绿）：

```
阶段轨迹  {"drafted":"1920-1","promulgated":"1920-9 (选 a)","journalOpenedAt":"1920-9","done":"1920-9"}
```

门控逐条验证：未起草时宣读事件不触发；未宣读时辩论事件不触发（**阶段顺序成立**）；
只有选项 a 开日志；顾问行动只推进不开启；日志开启当回合不误判失败。

> **一处需要你判断的观察**：一次正常对局里，`statuto` 会通过 `ev_strike`（劳动法）
> 与 1920-06 分岔门累积到 2，因此阶段 3 的辩论事件会**在 1920-09 同月**触发，
> 日志随即完成（`statuto 3` / `lavoro 3`）。也就是说四阶段在**同一个月内压缩完成**。
> 这是「条件平行推进」而非「日历推进」的结果——若你希望它们真的跨月，
> 需要给阶段 3 加一个 `cooldown` 或日期下限。

### 3.10 第四步实施结果：危机双轴拆分

**改前**：意大利武力收复与法西斯政变**共用 `order.coup` 一个数值**，里程碑文案只按

**改后**：两根独立累积的轴。

| 轴 | 字段 | 驱动公式 | 触发的事件 |
| --- | --- | --- | --- |

```
subversionDelta = clamp[−6, 20]( −6
                  + 0.30 × 法西斯小队
                  + 0.35 × max(0, 暴力 − 25)
                  + 0.50 × max(0, 法西斯派影响力 − 15)
```

### 3.15 增补 A：派系影响力零和 + 漂移必须可归因

**两条硬性规则**（引擎强制）：

1. **影响力是零和转移，不是加减。** 影响力是「固定 100 的份额」，任何变化都从其他派系按**各自当前份额比例**扣除（或按比例分给它们）；某派系不够扣时先扣到 0，余额继续分摊。
   唯一原语：`R.adjustFactionInfluence(state, 目标, delta)`——**全仓没有第二处写 `inf` 的地方**（`grep` 已验证）。
   参考实现：`D:\cnt-fai-1931_-spanish-republic-simulator8.15\src\game\utils\factionEffects.ts` 的 `adjustFactionInfluence`。
   原有写法是裸 `inf += x` + `normalizeFactions` 全体重标定——**那是缩放不是转移**，「−3」根本不成立。

2. **自动漂移必须挂在日志或法律上。** 引擎里没有无主的自动派系变化。此前 `R.factionDrift` 每回合无条件执行，玩家在界面上看不到任何出处；现已**删除**，改为 `impresa` 日志的 `monthly` 效果（法西斯派 +0.125~0.275/月，其余四派按 0.22/0.62/0.16/0.22 让出，总和恰好 0），日志面板会打印这条效果。

> **注意**：日志未激活或已完成时其效果不执行，所以漂移会随 `impresa` 一起结束。若要它贯穿到 1922 年，需改挂生命周期更长的日志。

**过程中查出的自身 bug**：第一版 `adjustFactionInfluence` 每次调用都把所有派系取整，于是 +0.125/月 被塞进目标自己的取整余数里**永远不累积**（实测 `实际转移 0.1250` 但 `法西斯 17 → 17`）。改为内部存浮点、取整交给显示层（界面本就用 `toFixed(0)`/`round1`）。

验证：`.analysis/check_faction_zerosum.js` —— 加上去的量现在**精确**等于请求值（+3 就是 +3），零和关系在 1e-6 容差内成立，级联、边界、40 次连续变动后合计仍为 100。

### 3.19 增补 E：`batchFactionInfluence` + 删除「飞越亚得里亚海」

**（一）批量零和转移 `R.batchFactionInfluence(state, deltas)`。**

起因：「宣传攻势」的《铁头》选项写「未来主义 +5／阿迪蒂 +3」，实际只落地 **+4.09／+1.41**。
原因是 `adjustFactionInfluence` 一次只搬一个派系，同一补丁里的两个增益互相蚕食——
未来主义 +5 要从其余四派按比例抽（阿迪蒂也在内），随后阿迪蒂自己 +3 又要为「合计 100」让路。

批量版把同一补丁里的所有增减**一次性结算**：

1. 每个请求先按可用余量夹取
2. **未被本补丁触及的派系是捐赠方**；把它们的份额整块收进池子
3. 每个增益从池子里拿**它申请的数额**（不够时全体按同一比例缩减，比例关系保持）
4. 池子余额按捐赠方**付款前的份额**比例退回
5. 只做钳制，**不取整**

`applyEffect` 现在会先数一遍补丁里的 `inf` 键：**多于一个就走批量**，只有一个仍走单目标路径。
实测《铁头》现在精确落地 **+5.00／+3.00**。

**过程中修掉三个自己引入的 bug**（都是我先写错再查出来的，记录在此以免重蹈）：

| # | 症状 | 原因 |
| --- | --- | --- |
| 1 | 合计变成 **111.43**、有派系被清零 | 捐赠方的份额**从未被扣**，增益凭空造出点数 |
| 2 | `impresa` 月度漂移完全不生效 | 漂移触及**全部五派**（法西斯 +d，其余四派 −d），此时「未触及的捐赠方」为空集 → 池子为 0 → 所有增益被缩放到 0 |
| 3 | 漂移仍然为 0，`applied` 里法西斯是 `0` | 一段早期遗留的**取整**代码把目标 `Math.round` 成整数：`Math.round(17.125) = 17`，子整数增量被抹掉。这也正是上一轮 `adjustFactionInfluence` 犯过的同一个错 |

**第 2、3 条只有靠 `smoke` 的「法西斯派应随时间增长」才暴露出来**——我改完批量后它立刻变红，否则这个「漂移静默归零」会一路溜到线上。这也说明那条断言值得留着。

**（二）删除行动卡 `az_volantini`（飞越亚得里亚海）。**

功能已被「宣传攻势」的选项 2（大规模空投宣传）覆盖，且后者带着真实抉择。
